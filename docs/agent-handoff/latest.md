## 수정한 문제

- 제품주 지시: 태블릿은 3학년부터 쓰므로 그리기 도구를 Sketchbook 수준 부분집합으로 고도화. 현장 확인 사항 "전원 펜(스타일러스) 사용"을 입력 설계에 반영.
- 범위: 브러시 4종+지우개(연필=신규 tool `pencil`에 S펜 필압 렌더), 굵기 5단(3/8/16/30/48)+그리기·지우개 굵기 분리 기억, 24색(기본/밝게 토글), 채우기·도형 UI 노출(엔진·서버 검증 기구현), 좌우 대칭(미러 op 쌍+그룹 되돌리기), 펜 모드(펜만 그림·토글 해제 가능), 두 손가락 핀치 확대+더블탭 화면 맞춤, 문구 중립화("다 그렸어요"→"완성" 등).
- perfect-freehand는 설치 승인이 없어 미도입 — 이미 저장되던 필압 데이터를 자체 세그먼트 렌더로 활용.

## 원인

- 기존 도구는 저학년 최소 구성(연필·크레용·지우개, 12색, 3단)이었고, fill/shape는 렌더러·validator에 있으나 UI가 없었다.
- 멀티에이전트 발견→반박검증 파이프라인(스키마·validator 변경 = 대형·위험 등급)에서 확정된 결함 29건을 같은 커밋에서 수정했다. 대표:
  1. 펜 없는 기기에서 두 번째 손가락이 와도 핀치가 시작되지 않음 → 진행 중 그리기 포인터를 마지막 좌표로 제스처에 승격.
  2. 도형 시작점 초록 점이 캔버스 픽셀에 그려져 썸네일·완성 PNG·AI 전송 이미지 오염 → DOM 점으로 교체.
  3. 펜 모드 영구 래치(해제 수단 없음) → 44px 토글 버튼으로 해제 가능, 펜이 다시 닿으면 자동 재활성화.
  4. 기존 `pen` 획에 필압 배율을 적용하면 실필압이 기록된 기존 작품 렌더가 ±50% 변함 → 신규 획만 `pencil`로 분리, `pen`은 균일 굵기 유지.
  5. estimateStrokeBytes가 최장 도구+미러 접미사에서 상한이 아님 → 여유분 확대 + 상한 테스트 추가.
  6. pointercancel이 (0,0) 좌표로 도형을 커밋 → 전용 핸들러로 폐기.
  7. 채우기가 pointerDown마다 커밋돼 손바닥 다접촉이 각각 fill이 됨 → 뗄 때 커밋 + 두 번째 터치는 핀치로 전환.
  8. 자동저장 썸네일이 화면 픽셀을 캡처해 미리보기가 섞일 수 있음 → 저장 이미지를 문서 오프스크린 렌더로 생성.
  9. 타임랩스 640px 래스터에서 픽셀 채우기 경계 판정이 스튜디오(1024px)와 어긋날 수 있음 → 1024로 통일.
  10. CSS: 모바일 도형 행 그리드 구멍(dense), 가로 모드 지우개 아이콘 붕괴, 도형 버튼 44px 미달(기본 2×2), 굵기 5버튼 고아 줄바꿈, 확대 배지와 수업 안내 겹침, 빈 캔버스 힌트와 도형 힌트 겹침 등.

## 남은 위험

- 배포 전환기: 구버전 캐시 클라이언트는 pencil/marker/watercolor/3·48 굵기가 든 문서를 "이 그림을 열지 못했어요"로 안전 거부한다. 배포 직후 학급 단위 새로고침 안내가 필요하다 (서버·클라이언트는 한 Worker로 함께 배포되므로 서버 선행 문제는 없음).
- 실기기 미검증: S펜 실필압 반응, 펜 모드 자동 감지, 크레용 반투명 경계 위 채우기 얼룩(허용오차 90)은 CDP로 재현 불가 — 갤럭시탭 실기기 확인 필요.
- 반투명 브러시 미리보기의 스냅숏(putImageData 1024²/move) 비용 — 저사양 태블릿 장획에서 프레임 저하 가능성. 발생 시 오버레이 캔버스 방식으로 교체 여지.
- 검토에서 기각된 발견 2건(canvas-view NaN 전파는 현 호출 경로에서 미발생, 가족 화이트리스트는 상류 검증으로 충분)은 수정하지 않았다.
