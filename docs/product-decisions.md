# Wiggle Web 확정 제품 결정

> 마지막 갱신: 2026-08-18
> 이 문서에는 사용자가 명확히 확정한 결정만 기록한다. 제안·추측·검토 중인 내용은 `pending-decisions.md`에 기록한다.

## 프로젝트와 제품 중심

1. 기존 Flutter 저장소를 수정하지 않고 `wiggle_web`을 별도 Git·GitHub 저장소로 운영한다.
2. 제품 중심은 `AI 그림 학습 도구 + 교실 창작 코칭 플랫폼`이다.
3. 이야기·가족 공유·구독은 그림 학습과 교사 코칭 이후 단계적으로 확장한다.
4. AI는 그림을 대신 완성하거나 평가하지 않고 아이가 호출했을 때만 돕는다.
5. 점수·순위·재능 진단·공개 SNS 경쟁은 만들지 않는다.
6. 핵심 학생 대상은 초등학교 3학년 이상이며, 읽기 수준 차이를 위해 그림·아이콘·음성·큰 터치 영역을 함께 제공한다.

## 학생 입장과 기록

1. 수업 코드와 학급 QR은 학급 입장 수단이며 학생 신원이나 작품 접근 권한이 아니다.
2. 작품과 과정 기록은 서버가 발급한 익명 학생 ID에 저장한다.
3. 학생 이메일·실명·학교명 없이 참여한다.
4. 그림 비밀번호는 3개를 사용하며 과거 4개 비밀번호 호환 기능은 제거한다.
5. 동물 선택지와 그림 비밀번호 선택지는 각각 10개를 제공한다.
6. 같은 기기 재접속과 공유 태블릿 학생 전환을 지원한다.
7. 메인 화면의 수업 코드와 학급 QR은 모두 학급을 확인한 뒤 같은 학생 입장 화면으로 이어진다.
8. 기존 학생은 해당 학급 안에서 `동물 + 별명 + 그림 비밀번호 3개`를 입력해 기존 익명 학생 ID와 작품을 연다.
9. 다른 공용 태블릿에서 같은 프로필로 들어가는 것은 예외 복구가 아니라 정상적인 재입장이다.
10. 학급 학생 전체 목록이나 입장 순서 번호를 학생 식별 수단으로 사용하지 않는다.
11. 학생 프로필이 하나도 없는 새 학급은 신규 프로필 생성 화면을 바로 열고, 프로필이 생긴 뒤에는 신규 학생과 기존 학생의 진입 버튼을 함께 보여준다.
12. 신규 학생과 기존 학생을 나누는 두 버튼 문구는 `새로 시작하기`와 `내 그림 이어가기`로 한다.
13. 기존 학생의 기본 재입장 수단은 학급 안의 `동물 + 별명 + 그림 비밀번호 3개`이며, 개인 QR이나 교사 재발급을 기본 복구 방식처럼 학생·교사 화면에 표시하지 않는다.

## 학습 과정

1. 학습 흐름은 다음 4단계다.
   - 1단계: 선·도형 기초 10개
   - 2단계: 따라 그리기 10개
   - 3단계: 관찰 그리기 10개
   - 4단계: 자유 창작
2. 별도의 `바로 자유롭게 그리기` 메뉴는 두지 않고 자유 창작은 4단계에서 제공한다.
3. 점선 가이드는 아이 그림과 분리된 레이어이며 숨기거나 거절할 수 있어야 한다.
4. 정지된 점선만 보여주지 않고 `짧은 연필 시범 → 점선 연습 → 독립 그리기`로 안내한다.
5. 점선 따라 그리기는 아이가 안내 요소를 그리는 순서에 의존하지 않아야 한다.

## 캔버스와 입력

1. 패드 사용을 중심으로 펜 입력 모드를 기본값으로 한다.
2. 손가락 그리기는 사용자가 명시적으로 선택할 때만 활성화한다.
3. 펜 모드에서 손바닥과 일반 터치는 그림을 방해하지 않아야 한다.
4. 두 손가락 제스처는 확대·축소와 화면 맞춤에 사용한다.
5. 모두 지우기는 확인 후 한 번에 지우며 한 번의 되돌리기로 복원할 수 있어야 한다.
6. 지우개는 실제 지워지는 범위를 네모 커서로 보여준다.
7. 색상은 갈색·민트색을 포함해 충분히 제공하고 선택한 색의 이름을 표시한다.

## 학생 UI

1. 학생 홈의 큰 메뉴 순서는 `이어 그리기 → 내 그림 → 활동 고르기`다.
2. 수업 마치기는 일반 메뉴에서 빼고 상단의 별도 행동으로 둔다.
3. 학생이 읽지 못해도 그림·아이콘·음성·큰 터치 영역으로 핵심 행동을 찾을 수 있어야 한다.
4. 대문과 학생 화면은 사용자가 제공한 그림책형 참고 이미지의 시각적 방향을 따른다.
5. 긴 설명은 줄이고 공간이 충분한 짧은 문장은 불필요하게 여러 줄로 나누지 않는다.
6. 신규 생성과 기존 학생 로그인은 태블릿 크기에서는 한 화면에 모든 입력을 보여주고, 휴대전화 크기와 세로 공간이 짧은 화면에서는 3단계 안내형으로 보여준다.
7. 음성 안내는 각 페이지 상단에 하나만 두고, 그 페이지에서 해야 할 일을 짧게 처음부터 안내한다. 동물·별명·그림 비밀번호별 개별 음성 버튼은 두지 않는다.
   - 안내 문장은 AI가 새로 만들거나 바꾸지 않고 제품에 확정된 시나리오 문장을 그대로 읽는다.
   - 재생은 한국어 음성을 우선 선택하고, 아이가 알아듣기 어려울 정도로 인위적으로 느리게 만들지 않는다.
8. 메인 화면의 현재 제목·문구·교실 그림·학생 안내·수업 코드 입력 카드·색감은 유지한다. 새 디자인으로 교체하거나 요소를 없애지 않고, 기존 요소의 폭·간격·정렬과 반응형 순서만 조정해 답답함을 줄인다.
9. `examples/KakaoTalk_20260817_182137151.jpg`, `examples/KakaoTalk_20260817_185428983.jpg`, `examples/KakaoTalk_20260817_194906484.jpg`는 각각 메인 화면, 학생 프로필 생성 화면, 학생 홈의 확정된 넓은 화면 시안이다. 세 화면은 추가로 재설계하지 않고 현재 구현이 시안의 구성·비율·위계를 제대로 재현하도록 수정한다.
10. 위 세 화면에 대한 사용성 피드백은 시안을 바꾸라는 새 디자인 요구가 아니라, 현재 코드에서 시안과 다르게 구현된 배치·크기·간격·잘림·음성 위치·반응형 문제의 수정 목록으로 사용한다.
11. 시안은 시각적 구성 기준이며 이후 확정된 기능 결정을 되돌리지 않는다. 수업 코드는 4자리를 유지하고, 학생 프로필이 있는 학급의 `새로 시작하기` / `내 그림 이어가기` 분기와 기존 학생의 `동물 + 별명 + 그림 비밀번호 3개` 재입장 흐름을 적용한다.
12. 설계 설명용 목업의 `우리 반 20명 목록이나 다른 학생의 그림은 보여주지 않아요`와 같은 주석은 실제 아이용 제품 문구로 사용하지 않는다.

## 교사와 메시지

1. 교사는 전체 학급 또는 특정 학생에게 텍스트 도움말을 보낼 수 있다.
2. 학생은 닫은 교사 메시지를 다시 확인할 수 있어야 한다.
3. 교사가 학생 작품을 보고 있을 때 학생 화면에 이를 알린다.
4. 음성은 후속 단계이며 텍스트를 기본 수단으로 유지한다.
5. 학생을 식별하는 최종 운영 방식은 아직 확정하지 않고, 먼저 교사가 학생 프로필을 확인하는 화면만 만든다.
6. 첫 교사 프로필 확인 화면은 동물, 별명, 생성 시각, 마지막 접속 시각, 전체 작품 수, 진행·완료 작품 수, 현재 진행 상태, 중복 별명 여부를 읽기 전용으로 보여준다.
7. 실명·출석번호·명부 연결 입력은 운영 방식이 결정되기 전에는 만들지 않는다.

## 배포 원칙

1. 기존 Flutter 저장소에는 변경을 만들지 않는다.
2. 검증된 소스만 GitHub `main`과 기존 Sites 프로젝트에 배포한다.
3. GitHub push와 Sites 공개 배포는 사용자가 명시적으로 요청한 경우에만 수행한다.
